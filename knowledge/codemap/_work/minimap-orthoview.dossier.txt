/**
 * The RTS camera: Beyond All Reason's Spring camera, as far as an orthographic Minecraft view allows
 * (lovish: "feels weird and isn't as smooth as BAR"). Bindings and config keys: design/camera.md.
 *
 * <ul>
 *   <li><b>Wheel</b> zooms toward the ground under the cursor (zooming out is from the screen centre, as Spring does,
 *       unless camera_zoom_out_from_cursor). The camera always owns the wheel over the map - a selection, a build
 *       ghost or Shift never re-route it. <b>Ctrl+wheel</b> tilts.</li>
 *   <li><b>Tilt follows zoom</b>: angled close up, near top-down zoomed out (camera_pitch_close / _far); Ctrl+wheel,
 *       Alt+middle-drag and Alt+pan keys add a tilt offset on top.</li>
 *   <li><b>Middle-drag</b> grabs the map; <b>Alt+middle-drag</b> rotates (yaw) and tilts around the screen centre.</li>
 *   <li>Keyboard pan (WASD / arrows), screen-edge pan with a short acceleration; pan speed scales with zoom.</li>
 *   <li><b>Tab</b> overview, camera anchors, and every "look at" (Space alert, portraits, control groups) glide.</li>
 *   <li><b>Shift never moves the camera</b> - in BAR it only queues orders. It used to tilt / swing the view, and a
 *       Shift+drag building line that reached a screen edge swung the camera side to side.</li>
 * </ul>
 *
 * All motion runs in one per-frame integrator ({@link #updateCamera}) on real frame time: zoom, yaw and tilt are
 * critically damped springs (exact solution, so 30 and 300 fps settle identically), panning is velocity-smoothed,
 * and glides are a 2D spring on the camera position. No allocations per frame. Everything is client-side camera
 * movement, so it behaves the same for a remote multiplayer client as for the host (the server accepts orthoview
 * movement from any client - ServerGamePacketListenerImplMixin).
 *
 * @author SoLegendary, adapted from Mineshot by Nico Bergemann <barracuda415 at yahoo.de>
 */

/**
 * The deterministic spec of one battlefield for {@code n} start slots (design/maps.md). Pure maths, no world access,
 * so the lobby preview, the builder and the fairness game test all read the same thing.
 *
 * Fairness by construction: slot i sits at angle {@code pi + 2*pi*i/n} on a ring of radius {@link #ring}. Every
 * terrain query is folded into the frame of its nearest slot - {@code u} along that slot's axis (centre outwards),
 * {@code v = |lateral offset|} - and the terrain is a function of (u, v) only, so the map is n-fold rotationally
 * symmetric with a mirror line through every slot. Mexes, capture sites, vents and pillars are listed once in slot
 * frame and rotated to every slot. Coordinates in the records are relative to the map centre.
 */
public final class MapLayout {
    public enum Surface { LAND, SAND, GRASS, CLIFF, MESA, WATER, LAVA, VOID, BRIDGE }
    /** One terrain sample, reused by the builder (no allocation per column). Heights are relative to the base. */
    public static final class Sample {
        public int height;
        public Surface surface = Surface.LAND;
        /** Fluid surface for WATER / LAVA columns (relative), filled from height+1 up to it. */
        public int fluidTop;
        /** May carry a tree (reclaim lane), never near a start. */
        public boolean forest;
        /** Folded slot-frame coordinates of the sample, for symmetric decoration hashes. */
        public double u, v;
    }
    public record Slot(int index, int team, int dx, int dz, double angle) { }
    /** A team's start box: an annular sector [a0, a1] x [r0, r1] about the centre (angles in radians). */
    public record Box(int team, double a0, double a1, double r0, double r1) {
        public boolean contains(double dx, double dz) {
            double r = Math.sqrt(dx * dx + dz * dz);
            if (r < r0 || r > r1)
                return false;
            double d = Math.atan2(dz, dx) - a0;
            d = ((d % TAU) + TAU) % TAU;
            return d <= a1 - a0;
        }
    }
    public record Mex(int dx, int dz, float value, int slot) { }
    public record Site(int dx, int dz, Kind kind) { }
    public record Spot(int dx, int dz, int size) { }
    static final double TAU = Math.PI * 2;
    /** Slot 0 sits due west (-x); the rest follow counter-clockwise on the map. */

/**
 * BAR-style strategic zoom (Beyond and Tabs).
 *
 * Past STRATEGIC_ZOOM_ENTER every visible unit is drawn as a team-coloured icon whose shape shows its role
 * (circle = worker/builder, square = melee, triangle = ranged, diamond = hero, star = commander) and buildings as
 * team-coloured footprint plates. Unit models (and with them their per-unit health bars, which are drawn from
 * RenderLivingEvent.Post) are skipped, which is what makes huge battles cheap to look at.
 *

 * T2 1.25x, T3 and heroes 1.6x, then the player's Icon size setting), and big units - T3, heroes, the commander,
 * anything 1.5+ blocks wide - keep their model until BIG_UNIT_ZOOM_MULT times further out, so a Colossus doesn't
 * pop into a dot at the same zoom as the chaff round it. Every icon sits on a 1 px dark outline so it stays
 * readable on snow and bright grass; selected units carry a white ring outside that, preselected a grey one.
 *

 * capitol, capture site) so a base doesn't read as a sheet of identical tiles; see drawGlyph.
